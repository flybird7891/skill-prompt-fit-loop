# Prompt Fit Loop

一个面向 Codex 的有限轮项目质量闭环 Skill。

Prompt Fit Loop 会根据用户提供的项目要求和满意标准制作实际成果，再使用可检查的证据逐项评分。当满意度低于用户设定的阈值时，它会在原有任务范围内继续修改；达到阈值或达到最大轮数后停止，并生成完整项目日志。

> 本 Skill 仅通过 `$prompt-fit-loop` 显式调用。
>
> 当前面向 Codex 开发和测试，其他 Agent 平台需要适配。

## 具体作用

- 消化原始提示词、交付成果和用户满意标准。
- 将需求划分为 `P0`、`P1`、`P2` 优先级。
- 制作代码、网页、文档、数据、设计等具体成果。
- 执行客观检查并记录验收证据。
- 使用证据逐项计算 AI 参考满意度。
- 未达标时自动修改原项目。
- 任一项 `P0` 要求未满足时，不允许判定通过。
- 单次运行最多执行 5 轮，避免无限修改。
- 项目结束后生成完整日志。

## 适用范围

适用于有具体交付物、且能够进行一定程度验收的项目，例如：

- 网页、小程序和交互界面
- 代码功能、脚本和自动化工具
- 文档、报告和说明材料
- 表格、数据清洗和分析任务
- 设计方案、视觉稿和创意作品

特别适合以下场景：

- 用户已经明确自己的满意标准。
- 希望成果不要停留在“差不多”的状态。
- 需要记录多轮修改和评分过程。
- 希望在有限轮数内尽量逼近原始需求。
- 需要可解释的验收证据。

以下任务不适合使用：

- 纯聊天、咨询或头脑风暴。
- 没有具体交付物的任务。
- 无法进行任何检查或验收的任务。
- 用户没有要求执行质量闭环的任务。

## 安装

### 1. 下载仓库

点击 GitHub 页面上的 `Code`，选择 `Download ZIP`，然后解压。

### 2. 安装完整 Skill 文件夹

将以下文件夹完整复制到 Codex 技能目录：

```text
prompt-fit-loop
```

Codex 全局技能目录通常为：

```text
$CODEX_HOME/skills/
```

Windows 默认位置通常为：

```text
C:\Users\<用户名>\.codex\skills\
```

安装后应形成：

```text
skills/
`-- prompt-fit-loop/
    |-- SKILL.md
    |-- agents/
    |   `-- openai.yaml
    |-- references/
    |   |-- project-profiles.md
    |   |-- run-log-template.md
    |   `-- satisfaction-rubric.md
    `-- scripts/
        `-- quality_gate.py
```

必须安装完整的 `prompt-fit-loop` 文件夹。只复制 `SKILL.md` 会导致评分细则、日志模板和计分脚本缺失。

### 3. 刷新 Codex

重新启动或重新扫描 Codex 技能。确认技能列表中显示：

```text
Prompt Fit Loop
```

## 使用方法

```text
$prompt-fit-loop

项目想法：制作一个任务管理网页
交付成果：可在浏览器中运行的完整页面

用户满意标准：
- 支持新增、完成和删除任务
- 刷新页面后任务仍然存在
- 桌面端布局清晰，无横向溢出
- 界面简洁，不使用弹窗广告

满意度阈值：0.85
最多轮数：3
```

没有明确提供的非阻塞信息会由 AI 记录合理假设后继续。会显著改变成果的缺失信息，最多集中询问一次。

## 配置

| 配置 | 默认值 | 允许范围 |
|---|---:|---:|
| AI 参考满意度阈值 | 0.80 | 0.50–0.95 |
| 最多轮数 | 3 | 1–5 |

当 AI 参考满意度大于或等于阈值，并且所有 `P0` 要求都已满足时，运行成功停止。

## 评分方式

每项需求按以下状态评分：

- `met`：完全满足，计 `1.0`。
- `partial`：部分满足，计 `0.5`。
- `unmet`：未满足，计 `0.0`。
- `unverifiable`：无法验证，计 `0.0`。

每项需求必须附带证据，例如：

- 构建或测试结果
- 页面截图或交互结果
- 文件内容检查
- 数据计算结果
- 运行日志或控制台状态

默认优先级权重为：

| 优先级 | 默认权重 |
|---|---:|
| `P0` 关键要求 | 3 |
| `P1` 重要要求 | 2 |
| `P2` 次要要求 | 1 |

用户明确提供权重时，以用户设置为准。

## 工作流程

1. 提取并合并需求。
2. 冻结带有优先级的验收清单。
3. 制作第一版成果。
4. 执行客观检查。
5. 计算 AI 参考满意度。
6. 低于阈值时修改项目。
7. 达到阈值或达到最大轮数时停止。
8. 生成最终日志。

第一版成果算第 1 轮，后续每次修改并重新验收进入下一轮。

## 输出日志

项目结束后，会在目标项目中生成：

```text
quality-loop/<YYYYMMDD-HHMMSS>/
|-- report.md
`-- state.json
```

日志包括：

- 原始提示词快照
- 合并后的有效项目规格
- 每项需求的优先级和证据
- 项目阶段时间线
- 每轮修改内容
- 每轮 AI 参考满意度
- 未解决问题
- 最终结论和停止原因

## 注意事项

- “AI 参考满意度”是根据需求、标准和证据计算出的结果，不等于真实用户问卷。
- 用户主动提供的满意标准优先于 AI 推导的通用质量偏好。
- 任一项 `P0` 要求未满足时，即使平均分达到阈值也不能通过。
- 达到最大轮数后仍未通过时，会停止修改并如实报告。
- 模糊标准会被转换为可观察条件，但不能脱离用户原始要求。
- AI 评分不能替代金融、医疗、法律、安全等领域的专业验收。
- 不要在提示词、项目文件或日志中提交密码、令牌、私钥等敏感信息。
- 不保证在其他 Agent 平台直接运行；跨平台使用需要单独适配和测试。
