# Prompt Fit Loop

一个面向 Codex 的有限轮项目质量闭环 Skill。

Prompt Fit Loop 会先消化用户的原始提示词和满意标准，再制作具体成果，并通过有证据的 AI 评审计算成果与用户需求之间的符合度。当满意度低于用户设定的阈值时，它会在原有项目范围内继续修改；达到阈值或用完最大轮数后停止，并为整个项目生成完整日志。

> 这个 Skill 仅在显式调用 `$prompt-fit-loop` 时启用。

## 具体作用

### 1. 消化需求与满意标准

- 提取项目目标、交付物、限制条件和验收要求。
- 支持用户直接提供自然语言满意标准、优先级、禁止事项和参考资料。
- 区分原始要求、后续补充要求和 AI 推导的验收细节。
- 保留原始提示词，并生成可追溯的有效项目规格。

### 2. 建立评分基线

- 为每项要求设置 `P0`、`P1` 或 `P2` 优先级。
- 每项结果必须附带实际证据，例如测试结果、文件检查、页面截图或运行行为。
- 用户主动提供的满意标准优先于 AI 推导的通用质量偏好。

### 3. 制作并验收成果

- 完成代码、网页、文档、数据、设计或其他具体交付物。
- 先执行客观检查，再由 AI 对照原始需求逐项评分。
- 最终结果会标记为“AI 参考满意度”，避免把模型评分误认为真实用户问卷。

### 4. 自动进行有限次修改

- 满意度达到阈值且所有 `P0` 要求均满足时立即停止。
- 未达标时，根据具体缺陷和验收证据修改原项目。
- 单次运行最多 5 轮，不会无限循环。
- 任一项 `P0` 要求未满足时，即使平均分达到阈值也不能判定通过。

### 5. 生成完整项目日志

项目结束后会在目标项目中生成：

```text
quality-loop/<时间>/
|-- report.md
`-- state.json
