# 项目类型验收指南

识别交付物类型后，读取最相关的部分；混合项目可以组合多种验收方式。优先检查实际产物，不以文件存在代替可用性。

## 代码与软件

- 检查构建、类型检查、语法检查和现有测试。
- 运行关键路径；涉及交互或界面时检查实际行为。
- 阅读失败日志，不以“命令已执行”代替“检查已通过”。
- 证据记录命令结果摘要、关键输出和实际修改文件。

## 网页与交互界面

- 在可用浏览器中打开页面，检查桌面和必要的小屏布局。
- 验证用户要求的交互、表单、导航和错误状态。
- 检查控制台错误、资源加载、可访问性和明显溢出。
- 证据使用截图、页面文本、交互结果和控制台状态。

## 文档与文字成果

- 对照用户要求检查结构、完整性、语气、受众和长度。
- 检查目录、链接、交叉引用和术语一致性。
- 对声明性内容核对来源或内部一致性。
- 证据记录章节、文件位置和具体检查结果。

## 数据、表格与报告

- 核对字段、单位、格式、公式、汇总和异常值。
- 重新计算关键指标，确认可复现。
- 检查空值、重复值、日期和数值类型。
- 证据使用校验结果、关键统计量和实际文件。

## 设计与创意成果

- 检查用户明确提出的尺寸、用途、颜色、风格、禁止项和参考物。
- 查看实际视觉结果，不只看提示词或设计说明。
- 无法自动验证的主观部分必须转成可观察条件；仍无法判断时不得直接通过。
- 证据使用截图、对比结果和明确的视觉检查记录。

## 其他成果

从用户满意标准和交付物用途推导最小充分检查。至少确认：

- 文件可以打开或使用。
- 核心要求确实存在。
- 禁止事项没有出现。
- 证据能够对应回具体需求。

如果环境不支持任何可靠检查，将相关要求标记为 `unverifiable`，并按评分规则处理。
