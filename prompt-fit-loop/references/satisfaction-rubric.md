# 满意度评分细则

评分的是“成果对原始提示词与用户满意标准的符合度”，不是 AI 对作品的总体喜爱程度。

## 需求清单

每条需求至少包含：

```json
{
  "id": "R1",
  "text": "必须满足的要求",
  "priority": "P0",
  "source": "user-original",
  "evidence": "可检查的证据"
}
```

来源使用便于审计的标签：

- `user-original`：用户原始提示词。
- `user-satisfaction`：用户主动提供的满意标准。
- `user-addition`：任务过程中补充、且已合并的要求。
- `ai-derived`：AI 为验证模糊要求而推导的可观察条件。
- `reference`：用户提供的参考材料。

`ai-derived` 只能细化验证方式，不能增加用户未要求的新审美偏好，也不能覆盖用户标准。

## 优先级与默认权重

- `P0`：关键要求，默认权重 `3`。
- `P1`：重要要求，默认权重 `2`。
- `P2`：可选或次要要求，默认权重 `1`。

用户明确给出数值权重时使用用户权重。用户只使用“必须、重要、可选”时映射为 `P0/P1/P2`。AI 推断优先级时必须在日志中记录判断依据。

## 单项评分

- `met`：`1.0`，有充分证据证明完整满足。
- `partial`：`0.5`，存在不影响核心用途的明确差距。
- `unmet`：`0.0`，未满足。
- `unverifiable`：`0.0`，无法获得可靠证据。

`P0` 只有在 `met` 时才算通过；`partial`、`unmet` 和 `unverifiable` 都触发否决。

## 总分与门禁

总体满意度为加权平均值：

```text
满意度 = Σ(需求权重 × 单项分数) / Σ(需求权重)
```

通过必须同时满足：

1. 满意度 `>=` 用户阈值。
2. 不存在未完整满足的 `P0` 要求。

用户阈值默认 `0.80`，范围 `0.50–0.95`。阈值恰好为 `0.80` 时，`0.80` 本身视为通过。

门禁结果：

- `pass`：达到阈值且无 `P0` 否决。
- `revise`：未通过且当前轮数小于最大轮数。
- `stop_failed`：未通过且已经达到最大轮数。

## 评审要求

先执行确定性检查，再执行提示词符合度评审。独立审查应只拿到原始提示词、有效规格、验收证据和实际产物，不沿用制作阶段的自我判断。

最终满意度以独立审查结果为准。制作阶段的自我评分、独立审查分数和两者分歧都应记录。无法使用独立审查时使用 `single_reviewer` 模式，并明确其限制。

每轮修改后重新评分。记录分数变化、已修复项、仍未满足项和 `P0` 状态，避免用其他项目的进步掩盖当前缺陷。

## 模糊标准

对于“简洁、自然、高级、有质感”等主观要求，将其转换为可观察条件，例如尺寸、信息层级、交互行为、禁止元素或参考对比。转换必须来自用户提示词、用户标准和参考材料。

如果模糊标准会显著改变成果且无法合理推断，集中询问一次。不要在多轮中反复用新的 AI 偏好提高标准。
